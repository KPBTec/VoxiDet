¿Por qué VoxiDet?

Detección real, no el AMD nativo de Asterisk

El AMD nativo de Asterisk decide con reglas de timing fijas. VoxiDet analiza el audio real de cada llamada — con IA de respaldo cuando la energía sola no alcanza.

Detección en 2 capas

Capa 1: energía de audio, sin costo, resuelve ~70% de las llamadas en menos de 100ms. Capa 2: transcripción real como fallback para el 30% restante, dudoso por diseño.

7 proveedores ASR con fallback

Deepgram, Groq, Fireworks, Together, OpenAI, y Vosk/Sherpa en local (costo $0, incluye Whisper large-v3 completo como opción de máxima precisión). Si el proveedor configurado falla, reintenta automáticamente con otro activo.

Batch o Stream, por cliente

Batch: confiable con 150+ agentes simultáneos, la opción recomendada. Stream (EAGI): más rápido para volúmenes menores. Se cambia desde el panel sin tocar Asterisk.

Transcripción sin costo de latencia

Toda llamada queda transcripta para auditoría, incluso cuando la capa 1 ya resolvió sola — corre en segundo plano después de responder a Asterisk, nunca agrega latencia real.

Auto-actualización del AGI

Se instala una sola vez por nodo Asterisk. Cada llamada verifica versión y se actualiza sola en segundo plano — nunca hay que volver a tocar el dialplan.

Firewall + fail2ban desde el panel

Reglas ALLOW/DENY por IP y servicio, más bloqueo automático de fuerza bruta (sshd y rechazos de la API) — sin editar nftables a mano.

El pipeline

Cómo funciona, en cada llamada

Cinco pasos, del contestar al AMDSTATUS que decide el dialplan — todo dentro de la ventana de grabación, sin que el marcador note la diferencia.

1

La llamada contesta

El AGI verifica su versión (GET /amd/check) y se auto-actualiza si hace falta — sin tocar el dialplan ni reinstalar nada en el nodo Asterisk.

2

Graba 2.5 segundos de audio

RECORD FILE captura el WAV y lo envía por HTTP multipart a /amd — todo dentro del mismo tiempo que un humano tarda en decir "¿aló?".

3

Capa 1: energía de audio

Sin API, sin costo. Resuelve ~70% de los casos en menos de 100ms según la duración y forma de la señal de voz.

4

Capa 2: transcripción real (solo si hace falta)

Casos dudosos pasan por el proveedor ASR configurado del cliente. Si falla, reintenta automáticamente con otro proveedor activo.

5

El dialplan decide

AMDSTATUS (HUMAN / VOICEMAIL / UNKNOWN) queda en el canal de Asterisk — el dialplan conecta al agente o cuelga, sin intervención manual.

Panel de Administración

Todo el sistema, desde un solo panel

Dashboard, clientes, proveedores, firewall y calidad de detección — sin tocar Docker ni Asterisk para el día a día.

Dashboard
Salud del servidor (CPU/RAM/disco) y resumen del día — llamadas, HUMAN/VOICEMAIL, clientes activos.
Clientes
CRUD, API keys, toggle batch/stream por cliente, límites diarios de consumo.
Logs en vivo
Stream de cada detección en tiempo real: resultado, capa, proveedor, latencia y transcripción.
Keywords
Palabras y frases globales o por cliente que ajustan la clasificación de la capa 2.

Activo/inactivo y modelo actual de los 7 proveedores ASR de capa 2, con orden de fallback configurable.
API Keys
Cargá y rotá las keys de cada proveedor cloud desde el panel, cifradas en reposo — sin editar archivos.
Consumo
Costo estimado en USD por proveedor — visibilidad total del gasto en transcripción.
Firewall
Reglas ALLOW/DENY por IP o servicio, más IPs baneadas por fail2ban (ver/desbanear).

Seguridad

Capas activas por defecto

Nada de esto requiere configuración adicional al instalar.

1

X-API-Key + Redis

Auth de la API AMD: header validado contra Redis, con MySQL como respaldo. Sin API key válida, cero acceso a /amd.

2

Sesión firmada en el panel

Cookie firmada con itsdangerous para el login admin — sin JWT ni sesiones server-side que mantener.

3

Rate limiting + security headers

120 req/min en /amd, 60 req/min en /admin/ — protege contra abuso sin afectar tráfico legítimo. CSP, X-Frame-Options y demás headers estándar en cada respuesta.

4

IP whitelist por cliente

allowed_ips valida el origen de cada llamada a /amd — un cliente no puede usar la API key de otro desde una IP ajena.

5

nftables + fail2ban

Firewall gestionado desde el panel, más bloqueo automático de fuerza bruta en sshd y en la API — sin editar reglas a mano.

6

Secretos cifrados en reposo

API keys de proveedores ASR guardadas con Fernet — la clave de cifrado vive fuera de la base de datos, un dump de MySQL solo no alcanza para leerlas.

Instalación

Todo corre en Docker

Ubuntu 22.04 / Debian 12. No necesitás instalar Python, pip ni ninguna librería — todo dentro de los contenedores.

# Clonar y levantar git clone <repo> /opt/voxidet cd /opt/voxidet sudo ./deploy.sh
# Instalar el AGI en cada nodo Asterisk wget https://tu-dominio/install/TOKEN \ -O /var/lib/asterisk/agi-bin/amd_ia.agi chmod 755 /var/lib/asterisk/agi-bin/amd_ia.agi # Ver logs docker compose logs -f api
ComandoDescripción
./deploy.shInstala/actualiza todo: usuario del sistema, nftables/sudoers/fail2ban, migraciones, imágenes Docker

docker compose restart apiReinicia solo la API, sin tocar MySQL ni Redis
